## Findings

### 1. Envelope cap was still bypassable (fixed in #258)

The whole-envelope reducer bounded reasons and `failure.detail`, but the
last-resort record still copied `result.report`, `frame`, `final`,
`checkpoint_validation` and `outcome` without a bound. A synthetic envelope
with a 20,000-byte report locator serialized to **20,724 bytes** against the
8,192-byte cap. The fix truncates every string only after the named reductions,
preserves classification, the first divergent event identity and a bounded
report locator, and returns a minimal truncation contract when the cap is
smaller than any useful record. Regression:
`tests.test_agent_tools.test_pathological_report_locator_cannot_break_the_cap`.

### 2. Malformed checkpoint evidence still raised (fixed in #258)

`checkpoint_request_evidence(..., shadow=[], ...)` and a list/string seal raised
`AttributeError: 'list' object has no attribute 'get'`. A nested
`producer_events: 7` raised `TypeError: 'int' object is not iterable` while an
invalid checkpoint row was assembled. Both are now explicit `invalid`
problems (`malformed_evidence`) or an empty bounded producer list. Regressions:
`tests.test_m7_checkpoint_provenance.test_malformed_shadow_and_seal_fail_closed`
and `test_malformed_producer_events_do_not_raise`.

### 3. The published approval record was overstated

GitHub has no formal `APPROVE` review for #241–#257, and the earlier matrix's
"independent APPROVE" wording is not supported by the review records. The
Codex findings were resolved and author-verified; that is useful technical
evidence, not an independent approval. The audit verdicts below are technical
review evidence; they are not formal GitHub approvals. A green focused run does
not convert into approval, and an audit session's self-report does not either.

### 4. Documentation states were stale after the final merges

`docs/status.md` still described #256/#257 as open and the coverage matrix still
named `c289adf4` as current `main`, while #256 and #257 had merged at
`f0bfa16c` and `a0e3a4e8`. The matrix also named #255's head as `6b4c4bff`
instead of `090f2b52`. This follow-up corrects those states and records the
re-audited heads.

## Scientific state

### B2/B3 live-GL control — blocked

Recomputed from the sealed 904 case (`capture-c`, session `afd444f2…`, 327
events, 1728×1117):

| Observation | Live vs Metal (pixels / max) |
|---|---:|
| 11, tex:431 | 0 / 0 |
| 13, tex:432 | 0 / 0 |
| 14, fb:0 | 0 / 0 |
| 15, fb:0 | 4 / 1 |
| 16, fb:0 | 3,602 / 119 |
| 17, fb:0 | 7,484 / 130 |

The same-seal GL controls remain unqualified: `gl-c-comp-event14` vs live
checkpoint 15 is **5 / 1**; `gl-c-comp-event15` vs live checkpoint 16 is
**4,645 / 86**. Both pairs have zero alpha differences, but exactness requires
all four channels to be equal. The five-pixel residual is not parity.

Draw 14 has `depth.test=true`, `depth.write=true`, `gl_front=0x901`, cull
enabled back-face, and the capture marks `multisample=true`. Draw 1 targets
framebuffer 6 (texture 433/depth renderbuffer 3), not `fb:0`; the first `fb:0`
draw is 14 itself. The only `fb:0` depth prestate is the clear at event 7
(flags 7, depth 1, stencil 0, color 0,0,0,1), and the one-draw control's depth
clear to 1 is therefore consistent with it. The missing observation is the
drawable state: `GL_SAMPLES`, `GL_SAMPLE_BUFFERS` and bit depths were never
recorded, and prior-frame contents are not in the trace.

The 904 measurements above are historical and are retained unchanged. The
missing observations do not exist in the 904 seal, so they must not be
manufactured by creating a new capture with that historical seal. New
observations require a newly sealed capture, paired with a new original-API
control rendered from that capture's own stream, resources and checkpoint. Only
zero differing BGRA bytes between the new control and the new capture's live GL
permit the remaining Metal residual to be considered a renderer-side candidate.
Do not substitute a window or 10-bit FBO; both are different destinations.

## Residual P0 findings not fixed at these heads

Two correctness defects were found after the exact-head audit and are recorded
here as unresolved; they are not accepted behaviour and are not covered by a
green test run.

5. **Campaign claim ledger fails open on corrupt state.** `CampaignClaims.rows()`
   silently drops unparseable rows and returns an empty list when the ledger is
   unreadable, so corrupted, truncated or replaced state is treated as fewer
   attempts. That can reset the validation budget. The fix must fail closed,
   keep lock-based atomicity and idempotent claims, and add cross-process and
   interrupted-write regressions.
6. **Original-API control authority is not authenticated.**
   `gfx_gl_control_qualification.qualify()` decides solely on pixel equality
   plus optional drawable/prestate records. It does not bind the live and
   control images to the sealed frame, stream, resource, checkpoint, or to an
   authenticated original-API execution. An exact image from a different seal
   could therefore qualify and authorize Metal blame. Exact BGRA comparison,
   authenticated control qualification and permission for causal attribution
   must be separate outcomes; missing evidence must be explicitly unqualified.

Both findings remain `unresolved` until a reviewed fix is merged.
