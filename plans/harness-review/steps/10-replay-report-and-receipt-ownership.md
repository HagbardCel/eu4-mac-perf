# 10 · Consolidate shader receipts and repeated replay-report data

**Objective.** Keep one maintained definition of shader artifact identity and one stored copy of heavy diagnostic fields per new replay report. This concerns shared representation; acceptance must still recompute evidence independently. Ship the two changes separately. Step 01 remains the prerequisite for trusting a correction.

### One definition of shader receipt fields

1. In automation/m6_frame.py, shadow_coordinator defines a nested artifact_digest at line 2209. The module-level artifact_digest at 2452 walks the same sorted relative paths, excludes ready and shader-receipt.json, and hashes each relative path, NUL, hex file digest and newline. The continuous coordinator uses the module-level alias. automation/m7_continuous.py:293 and automation/gfx_replay_case.py:1255 separately define _receipt_shader_identity and return the same three fields. The case packager and verifier call the latter. Keep m6_frame, which already owns artifact_digest, as the production owner. Eliminate the nested implementation and both wrapper definitions. Reuse the owner at the single-frame, continuous, sequence-replay and packaging call sites. Do not coalesce the distinct lifecycle/timeout logic of the coordinators.
2. Preserve the current path ordering, encoding, exclusions, empty identity for unavailable optional shaders, and required-file failure at live publication. The permissive optional wrapper cannot turn a missing mandatory report into a successful receipt. Retain the existing private alias only if a real supported caller needs it. Avoid the temptation to consolidate every unrelated hash reader; several distinguish missing files, exceptions and empty digests differently.
3. Exercise a nested shader tree, ready/receipt markers, reordered creation, missing shaders.json, altered MSL with unchanged report, missing optional directory and mandatory-directory failure. Pin independently precomputed digest and count in the test; the expected value must survive a bad production helper. Then package and verify a relocated sequence and tamper one shader. Existing tests.test_m7_shadow_receipt and tests.test_gfx_replay_case_sequence include the live contract and tamper path. Follow with tests.test_m7_continuous_replay and tests.test_m7_translation_cache.

### One stored graph per replay report

4. At automation/gfx_independent_replay.py:_replay_locked the success path copies graph, evaluation, checkpoints, validation, binding audit, state coverage, qualification and first divergence from diagnosis, then serializes diagnosis in full inside the same report. On the latest R/replay-1, each of those eight top-level values equals its nested value. replay-report.json is 6,166,943 bytes. Removing only the outer graph from a freshly indented serialization saves 2,534,459 bytes with the nested graph retained. This is measured disk output, not time saved. automation/gfx_replay_case.py:package also copies REPLAY_ARTIFACTS, reads report.get("graph"), copies checkpoint files from the outer rows, and rewrites portable paths. An unconditional deletion breaks readers or makes the packager rebuild a graph unnecessarily.
5. Implement a narrow report reader/serializer in gfx_independent_replay for the existing full shape and a versioned storage form with the graph under diagnosis. Read the newer graph once and expose the old public return shape in memory for API/CLI callers. Explicitly support failure reports and older reports with only top-level fields. Reject conflicting graphs on new writes. Avoid a new cross-file lookup: both views can be produced from one self-contained file. Update prepare_replay_output's owned-report schema recognition, package/relocation, CLI summary and case verifier/manifest enumeration wherever the new schema is consumed. Preserve legacy package bytes/digests. Only omit further duplicated fields once both views compare equal and the file is independently portable.
6. Test old/compact, success/failure and unexpected schema through normal CLI and packaging, including a case with moved directories and a report with divergent checkpoints. Assert identical graph, capture identity, paths, first writer, unsupported states, exact statistics and failure classification after loading. Preserve input/output-overlap protections. Run tests.test_gfx_output_safety, tests.test_gfx_replay_case, tests.test_m7_diagnosis and tests.test_correction_accept with the offline runner. Measure serialization against the frozen report without replaying EU4. Also note m6_frame's intentional shadow/continuous aliases in capture-report.json; they duplicate ~9.5 kB of compact JSON in this case. The cost does not justify a separate format migration.
7. Keep diagnostic versus acceptance semantics explicit. gfx_frame_compare.py has scale/region policies for older frame comparisons; m6_compare.py computes the sealed path's exact statistics. The CLI and shadow bridge both call the same native Metal ABI already. Neither pair warrants a new shared rendering or comparison framework.

Document the storage schema and keep a legacy serializer for an external consumer if needed. If compatibility work outweighs demonstrated usage, land the receipt consolidation independently and leave old report serialization enabled; do not add permanent dual-written reports.
