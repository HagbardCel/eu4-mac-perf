# 07 · Make native failures visible and measure verified progress

**Objective.** Preserve each distinct verification gate while reducing time to the first actionable result. Measure a component of the workflow only where its time and outcome can be attributed.

**Evidence.** B ran the focused test runner twice; transcript classification counted zero tests. A had three launch claims and three owned process records; a CLI heuristic estimated eight process starts. The portable CI offline gate occupied 253 of 285 s in the measured job. The local historical full gate took 902.6 s. Several native suites can skip an eligible build failure. Linux and macOS profiles provide different coverage. [Profile and mandatory tests](../../../automation/test_profiles.py) · [deduplicating runner](../../../automation/test_runner.py) · [session analyzer](../../../automation/dsh_efficiency.py) · [CI](../../../.github/workflows/profiler.yml)

**Implementation order**

1. Inspect native `setUpClass` paths in `test_m7_metal_replay`, `test_m7_continuous_replay`, `test_gfx_frame_trace_writer`, `test_gfx_texture_versions`, `test_m7_shadow_receipt`, `test_m7_target_lifetime` and `test_replay_blob_verifier`. Check declared platform, SDK/compiler/dependency/usable hardware requirements separately. Preserve justified skip reason and capture platform coverage in the run record. After satisfied prerequisites, a required compiler/linker failure must fail with argv, status and bounded stderr plus full log path. Keep platform-independent tests runnable. Share a tiny helper only across equivalent checks.
2. Add regressions that simulate declared missing prerequisite, compiler nonzero after a successful eligibility probe, executable launch failure and a passing build. Run native suites on eligible macOS and check the recorded executed/skip counts. Require a real native run when qualifying a native renderer change; the present Linux CI gate cannot attest a device pixel result. No requirement for a new continuously running macOS service follows from this review.
3. Route feedback by the four tiers in the assessment and roadmap. Preserve full offline gate, mandatory IDs/count floor, frozen outputs, goal/tools plugin tests and negative controls. Record per-module/setup/build elapsed time from the *same* invocation where feasible, sharing cached builds only across identical source/header/flags/toolchain/architecture identities with an invalidation test and a cold control. Deduplicate an identical active test using `test_runner`. Measure before changing the single CI job or sharding. No suite is proposed for deletion.
4. Extend `dsh_efficiency` to recognize `python[3.14] -m automation.test_runner`, nested jobs and wrappers. Join to test runner IDs, reservation/claim records, launcher PID/termination, producer receipts, checker result and explicit operator waits. Distinguish CLI request from physical spawn, build request from actual invocation/cache hit, completed replay from refused/pre-spawn/invalid, expected nonzero verdict from tool failure. Include data source and `unknown` for unmatched events. Emit interval unions for wall time; summed waits are a separate metric. Keep legacy heuristics explicitly labeled when no receipts survive. Make local-only traces a supported input without publishing raw model/tool content.
5. Use the existing analyzer and campaign manifests for a small before/after trial. Pin repository and infrastructure SHA, model/version/config, prompts, case/stream/shader/binary digests, host, power/display, test profile and budgets. Vary only the proposed intervention; use identical starting knowledge, fresh sessions and isolated output roots. Record cache state; pair cold with cold and warm with warm. Use at least three paired trials per task for an initial range/median, retain every blocked/failed trial, and disclose order and model nondeterminism. Avoid attributing causality by comparing two different live presents or dividing clocks from overlapping sessions.

**Benchmarks and endpoints**

| Task | Success and primary denominator | Secondary evidence |
|---|---|---|

| Fault and interruption matrix | All stale, foreign, alpha-only, unsupported, interrupted and permissive-policy negatives must refuse an exact claim on every trial | False match/false tool-failure counts, lost/duplicate actions, cleanup time and resume attempts |

**Acceptance and rollback.** The A fixture yields three confirmed game starts when joined to its records and excludes help; B through seq 1555 yields three runner invocations (seqs 721, 913, 1517), zero confirmed starts and distinguishes unmeasured GPU time. Produce a coverage/timing summary for one already required full gate. Compare before/after outcomes and costs on the same tasks. No faster run qualifies with a false acceptance, lost control or smaller tested scope. Focus `tests.test_test_runner`, `tests.test_test_profiles`, `tests.test_dsh_efficiency` plus affected native suites; run the normal integrated gate once. Keep legacy fields for readers, make timings optional, and disable build reuse if identities differ. The native failure classification fix should ship independently of metrics or caching.
