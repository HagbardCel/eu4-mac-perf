# 09 · Reclaim repeated capture payloads and keep reproducible evidence

**First cleanup target.** On 20 November, the ignored directory `.local/m6/live/ptr-02` contained 1,287 separately named, distinct-inode `resolve-source-*.bgra` files. I streamed every file through SHA-256. All 1,287 were 30,882,816 bytes, all with digest `4e2442de5e0aa9635533c68be5000e6d001b28b5412adb90b47d8db34246928b`. The local resolve receipt gives 3456×2234, consistent with four bytes per pixel. One payload plus the original filename sequence can represent **39,715,301,376 fewer logical payload bytes (36.99 GiB)**. Physical free space depends on APFS sharing, archive overhead and snapshots. The directory also contains other images, shader observations and JSON; those need their own inventory. Their similarity has not been established.

**Why this comes before a general storage service.** analysis/m6/campaign-record.md already records an earlier cleanup of ~101 GB of resolve dumps from three other runs. Commit d6ac2d91 removed the numbered resolve-source writer in benchmark/. The same filename pattern is absent from the current tracked producer. Clean up the surviving old output. A new always-on deduplication subsystem would impose a cost on every new capture for a writer that has already changed.

1. **Protect active work first.** Record the current baseline/control pins and verified restore path from Step 02. Check campaign state, leases, open producer jobs and required regression manifests. Only select the closed ptr-02 batch for the first operation. Preserve ordering, duplicates, session/resolve metadata and original relative names. Do not classify an unreferenced path as regenerable solely from a text search.
2. **Create a reversible archive outside the disposable worktree.** On local operator storage use a temporary sibling directory. Write the unique BGRA once, a manifest listing all 1,287 relative paths, size and SHA-256, and include each of the other files with its original content and digest. A standard tar archive with hard-link entries in immutable staging is sufficient. The original live/output directory must never be the hard-link target for future writes. If mutation, path aliases or symlinks are encountered, handle explicitly or refuse publication. Use a temporary destination, compare manifests and publish atomically. Never put proprietary payloads in Git.
3. **Prove recovery before cleanup.** Extract to a distinct temporary root. Check every expected name, length, byte digest, and all non-BGRA files. Verify numbered entries including first and last, run the historical reader if available, and record a restore command/path and archive digest in the local evidence index. Cold storage can maintain ordered filenames as archive hard links; restore writable independent files or copy-on-write clones before any tool that mutates frames. Where external tools require the original directory, preserve that interface via explicit restore. Only after operator-authorized retirement of the redundant output can free space be measured. Preserve the manifest and verified archive thereafter. Partial copy or failed restore leaves the original authoritative.
4. **Stop duplicating session exports.** Under artifacts/session_logs the ZIP includes the byte-identical v4 JSONL and both media PNGs. Use the ZIP as the durable copy and extract by session/digest to a temporary view for automation/dsh_efficiency.py and image inspection. Test a fresh extraction against all three member hashes and the 201-call/blocked-goal baseline. Remove only the validated regenerable view during authorized cleanup. Keep trace exports distinct from the call-graph/callsite/foundation archives. This saves local bytes only.
5. **Reduce the tracked tree selectively.** analysis/m6/live-title-metal-postfix.png has IHDR, IDAT and IEND only. An in-memory PNG re-encode at compression level 9 preserved 3456×2234 RGBA and every decoded byte, shrinking 17,870,276 → 12,009,448 bytes. The original remains at 11a5a220. A tracked literal search found neither filename in a consuming source nor its raw SHA-256. Check manifest glob/tree consumers and preserve original commit/blob identity. If a consumer authenticates file bytes or original container is the evidence, keep it unchanged. Otherwise commit **only** this lossless re-encoding in a separate content-review change at the same path. Compare dimensions, mode, color/ancillary chunks and decoded digest including alpha. Preserve the 1728×1117 pre-fix reference and button crops used in tests/test_m6_live_accept.py. Measured potential reduction is 5,860,828 working-tree bytes for the large image; a new commit retains the old blob in history. Avoid history rewriting, LFS migration or blanket PNG recompression.
6. **Prevent renewed growth at the producer.** For future new diagnostic dump outputs reuse the existing opt-in selected-event mechanism and byte/count budgets (automation/m6_frame.py; benchmark/eu4_gfx_frame_trace.c). For repeated observations store one verified payload per digest while retaining one ordered observation per event. If the budget cannot fulfill a required GL checkpoint, report incomplete with its event/resource and reason. Never coalesce two logically distinct events for acceptance. Apply this only to writers that exhibit the problem.

**Verification and done.** Re-run a read-only inventory with `du -sk .local .local/m6/live/ptr-02 artifacts`, and compare distinct file identities and manifests before/after. Exercise duplicate and distinct payloads, skipped numbers, missing or corrupt payloads and a failed/interrupted restore on scratch fixtures. Run `python3.14 -m automation.agent_tools eu4_replay verify --case <pinned-case>` after relocation and the Step 02 negative cases. For the PNG run the offline module tests.test_m6_live_accept using the roadmap's runner. Record original/archived/restored logical bytes plus actual allocated-space delta, and the resulting Git tree-size delta for the separate PNG change. Success requires a verified restore and a smaller working set. Roll back by restoring from the verified archive or original Git blob. No artifact is removed by this review.
