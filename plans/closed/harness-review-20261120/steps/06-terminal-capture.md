# 06 · End an owned capture at its authoritative terminal result

**Objective.** Release the game and restore the display as soon as the requested shadow comparison or terminal health failure is durable. The elapsed opportunity is approximately 185–203 s per historical capture, including cleanup. Actual savings require measurement.

**Evidence.** A made three one-use launches; the gaps from coordinator report to launcher report sum to ~588 s. In all three runs the auxiliary ops recorder returned zero events, while the shadow produced a sealed case. `_wait_pair` watches two ops-related summary files. `run_ops` ignores its boolean as a semantic verdict and terminates the owned handle in its cleanup path. The later noncontinuous capture 904 shows an additional 78.9 s report-time gap. Handle both modes. The original ops acquisition contract is still used. [Wait and cleanup](../../../../benchmark/eu4_gfx_startup_trace.py) · [capture and continuous supervisor](../../../../automation/m6_frame.py) · [prior one-case finding](../../../closed/harness-review/steps/08-stop-on-shadow-result.md)

**Implementation order**

1. Where `m6_frame.capture` starts the shadow coordinator and delegates to `startup.run_ops`, explicitly select the owning consumer. Add an optional terminal condition for this capture mode. Retain the default summary-pair wait and watchdog for ordinary ops callers. Reuse the existing handles, run root, deadline and game identity.
2. Publish the terminal `shadow_coordinator_continuous` result atomically after the requested case/receipt is closed. Require a run/session binding, expected sealed frame/range, coordinator status and completed output inventory. Multi-frame runs remain active through their requested boundary or explicit failing frame. An early valid prefix is not completion of later requested frames. Recognize terminal failures (rejected draw, command, validation, resolve/readback, process death) as failure even if a prefix is valid. Invalid/foreign/stale files are never terminal success.
3. Extend `_wait_pair` or its immediate caller to inspect owned coordinator termination/result alongside game death, watchdog and the original wait target. Propagate the exact stop reason and timestamps. Distinguish requested differential outcome, ops recorder status, game exit/reaping and cleanup status in `capture-report` and launcher reports. Report incomplete optional traces honestly. A parse race needs a bounded retry; coordinator exit without a valid terminal record is an instrumentation failure.
4. Retain one-use launch claim, host-wide lease, finally cleanup, PID ownership, settings hashing and restoration. Ensure one cleanup exception cannot prevent the remaining close/restore/release steps from being attempted and reported. Kill only the owned process after bounded graceful termination. Do not grant extra launch budget on terminal difference or timeout.

**Verification.** Focus `tests.test_gfx_startup_trace`, `tests.test_m7_continuous_supervisor`; follow with `tests.test_m7_continuous_coordinator`, `tests.test_m6_live_capture`, `tests.test_campaign_guard`, `tests.test_dsh_launch_safety`. Use simulated clock/handles and staged publication for all three recorded timing orders. Include positive terminal case without ops summary, ordinary ops mode, early seal, partial JSON, different PID/run, premature coordinator death, multi-frame prefix, failed readback, restoration exception and cancellation. Assert bounded wait, exact statuses, one termination and final lease availability. Use the next independently justified live diagnostic for a monotonic timeline from spawn to restore.

**Done and rollback.** Offline fixtures end within one poll plus cleanup after valid publication, retain both summaries in required-ops mode, and report outstanding failure on all negative cases. Record measured wall savings only after live confirmation. Roll back by selecting the established wait mode for subsequent captures; preserve all prior terminal records and independent acceptance criteria.
