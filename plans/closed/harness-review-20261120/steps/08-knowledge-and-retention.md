# 08 · Publish current knowledge and preserve replayable evidence

**Objective.** Give an agent one verifiable starting point per subject and let a second session reconstruct a pilot result without searching historical worktrees. The project already has status, evidence discovery, case locators, receipts and ADRs.

**Evidence.** `docs/status.md` leads with an older 615 interval, while the newest 616 evidence observes 14→15. A searched for a missing historical case; B later found A's outputs under a shared generic directory. The expanded and zipped A traces matched exactly. B's experiment tree alone used ~3.3 GiB at inspection, and the checked-in documentation, locally available artifacts and untracked working reports have different publication guarantees. [Status](../../../../docs/status.md) · [repository map](https://github.com/HagbardCel/eu4-mac-perf/blob/6d539a80c3a18fc352f5fc35d237c26fb01b6c06/docs/repo-map.md) · [locator](../../../../automation/case_locator.py) · [discovery](../../../../automation/evidence_index.py)

**Implementation order**

1. Put a short dated navigation and current accepted/partial/blocked capability table at the top of `docs/status.md`. Give each row a case/executable identity, scope, source and smallest missing discriminator. Label previously valid snapshots with their run dates. Preserve old paths/anchors used by campaign pins and review links. Confirm current qualification against the checker or latest independently verified artifact, especially where a mutable local report says a fix is complete.
2. Assign these canonical destinations. Link rather than recopy bulk traces or version-specific disassembly.

   | Destination | Content and first source to reconcile |
   |---|---|
   | `docs/eu4_renderer.md` | Original engine entry/caller map, draw lifecycle, program/texture/resource generation and observed state, keyed by executable. Start with `analysis/metal-census`, `reverse_engineering`, engine contracts and original GL capture. Explicitly mark inference and missing effects. |
   | `docs/metal.md` | Correctness backend, hook → seal → shadow → readback, typed state coverage, unsupported enums, shader pipeline, lifetimes, receipts, strict comparison and current qualification. Link `docs/metal-shadow-worker.md`, M6/M7 evidence and relevant ADRs. |
   | `docs/metal_optimized.md` | Prospective measured bottlenecks, constraints and qualification path against original GL and the faithful backend. Include a performance baseline only with an actual workload, host and comparison. Separate implemented experiments from future work. |
   | `docs/harness.md` | Supported DSH/OpenCode entry, recovery and close paths, focused runner, discovery, shortest useful replay/control, budgets, leases, and how to interpret compact results. Consolidate stable procedure from `AGENTS.md`, `automation/README.md` and plugin docs; leave concise entry references at existing paths. |
   | `plans/`, `plans/closed/`, `docs/decisions/`, `analysis/` | Active proposals, completed/superseded plans, durable choices, and dated analysis respectively. Keep frozen campaign manifests/report pins immutable. Annotate index entries with decision/implementation state before archiving a plan. |

3. Extend the existing case/pilot publication inventory only where fields are missing. Bind session and parent session, phase/cutoff, repository/binary/shader/driver, seal/stream, case, comparison, producer receipt, independent decision, and scripts/argv that generated derivatives. Link companion sessions explicitly and distinguish absence from deletion. Snapshot inventories by digest so a working report can continue evolving. Resolve shared cases read-only; store new experiment attempts under session-owned directories. Preserve required directory layout or give a verified restore map. Review distributability of raw proprietary inputs and private transcripts before promoting metadata.
4. Classify *referenced* authoritative cases, negative controls and first divergent checkpoints as retained. Keep compressed raw traces, relevant failure/cleanup records, build/recipe and versions needed to reproduce. Generated display tables and repeated derived shader/build copies are reproducible only after an isolated restore proves it. Before a later cleanup proposal, inventory references from active cases, regression manifests, reports, tests, scripts, frozen campaigns, docs and parallel worktrees. Mark unknown/unique dependencies retained. For identical expanded/compressed traces, verify archive extraction byte-for-byte and consumers' ability to read it. Use existing discovery/retention entry points; avoid creating a second object store or moving all old runs.
5. Trial on A and B plus one older independent case. From a fresh directory perform lookup, verify hashes, locate raw blobs or emit exact missing identities, recompute the event-15 comparison and find the source of a failed validation. Measure retrieval time and actual allocated space before and after any separately authorized archive action. Keep restores private. No artifact removal is part of this review or prerequisite for navigation improvements.

**Verification and done.** Use `python3 tooling/common/check_doc_links.py --strict docs plans/harness-review` and the runner for `tests.test_case_locator`, `tests.test_m7_evidence_identity`, `tests.test_dsh_docs`; then an offline restore/readback trial. Verify historical ADR and frozen manifest links, local-only evidence labels, a missing-blob negative and readable ZIP/export identities. Done when a new session can find the current scoped capability, underlying source and authoritative case without reading a historical narrative or scanning the filesystem. Roll back via index/redirect changes; keep originals until all pinned consumers and restore tests pass. No automatic retention age or deletion recommendation without reference and restore evidence.
