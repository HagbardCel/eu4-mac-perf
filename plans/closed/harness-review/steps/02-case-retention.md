# 02 · Preserve and resolve the next pilot's sealed evidence

**Objective.** Turn a published capture identity into a single verified case lookup across worktree disposal. T79's search lived 584.7 s. T184–188 read the rescue manifest, which excluded .local. Replaying a previous frame cannot supply a GL checkpoint it never captured, so measure retrieval separately from live captures.

1. Reuse automation/gfx_replay_case.py package_diagnosis, verify and manifest inventory, plus the relocation checks documented in analysis/m7/followup-b-portable-reproduction.md. Select the first-divergent case, each required exact control and any unresolved causal case explicitly. Pin the case under an operator-owned local evidence root outside disposable worktrees when publishing its handoff. Preserve original bytes, seal, shaders, graph, replay/diagnosis, policy and receipts. Preserve adjacent producer-bound replay as a separate input when the package has legacy_missing; never graft a producer identity onto different bytes.
2. During publication copy into a temporary sibling directory, check available size and package budget, verify after relocation, then atomically publish by seal/manifest digest. If already present verify before reuse. Commit the locator only after the copy is valid. On interruption leave the source usable and the pin absent. The current package uses about 526 MiB on this filesystem. Avoid duplicating the full ~1 GiB capture for every investigation. Make a size/identity summary available for manual retention decisions.
3. Add an explicit small locator under the configured evidence root, keyed by executable, session, frame and seal digest. Return relative path, manifest digest, verification state, originating run and limitations. Extend automation/evidence_index.py and the existing eu4_session discover filter to recognize these published locators; _session_dirs currently expects result.json. Read declared roots only. On lookup return available, missing local payload, digest mismatch or root unavailable. A negative search without a published locator is unknown. Never equate it with verified deletion. Hand the resolved case to eu4_case_inspect once.
4. Add a pre-disposal check to the operational procedure for removing worktrees. Identify unresolved/required pins first; retain source until independently relocated copy verifies. Do not sweep historical raw assets into Git. Concurrent publications of one digest must converge. Broken locators and insufficient space must identify the source case and recovery action.
5. In temporary synthetic roots, publish two cases with the same human-readable case_id but distinct sessions. Move/remove only the disposable test source. Resolve each separately, inspect with the existing CLI, compare verification and earliest divergence before/after; simulate interrupted copy, one corrupt byte, duplicate publish and missing root. For an authentic dry run use the preserved case and configured local destination. Keep archive and original intact.

**Commands.** Run focused tests.test_evidence_index and tests.test_gfx_replay_case using automation.test_runner. Follow with tests.test_agent_tools and tests.test_gfx_replay_case_sequence. Run `python3.14 -m automation.agent_tools eu4_replay verify --case <relocated-case>` without --replay-out.
