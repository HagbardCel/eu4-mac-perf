## Highest-impact findings

1. **Verified false equivalence in correction acceptance.** Starting with `CorrectionAcceptanceTests.test_one_pixel_fault_is_corrected_and_accepted`, using its mocked producer, exact candidate final and normal before/after claims, I flipped bit 0 of byte 0 in the candidate's `intermediate-event4-tex10.bgra` before invoking the fixture's `acceptance()`. The checker returned `requested=1, returned=1, matched=0, divergent=1, invalid=0` and still declared pixel perfection. The comparator found the difference. The verdict lost it. `automation/correction_accept.py:_qualification_axes,_evaluate` checks request reconciliation and final statistics. Its regression loop also tests exactness at the final image. Moreover, `_replay_evidence` directly reconciles the published plan, bypassing the graph-plan and binding checks in `gfx_independent_replay._checkpoint_request_state`. The producer receipt binds replay.json and the final readback but does not independently bind every intermediate byte. An omitted checkpoint or later overwrite must never manufacture success. See [01](steps/01-checkpoint-acceptance.md).
2. **Verified renderer state loss with authentic inputs.** The sampler key in `benchmark/eu4_gfx_frame_replay.mm:2617–2665` includes min/mag, S/T wrap and bias. The descriptor also uses R wrap, min/max LOD, compare mode and function. Grouping the pilot's captured samplers by the five key fields gives ten groups. One group contains max LOD **2, 7, 8, 9, 10 and 11**. Event 1 units 2 and 0 specify 10 and 7. Event 14 units 0 and 15 specify 11 and 8. Once two such descriptors are requested on this cache path, the first wins. The impact depends on actual sampling, mip availability and insertion order. There is no evidence yet that this explains any of the 607 pixels. Test cache order and clamp-sensitive inputs independently. See [04](steps/04-render-state.md).
3. **Verified evidence loss and configuration mismatch.** Discovery ran after the search was already expensive (T79, 100–102). The rescue manifest records 59 removed worktrees / 93.6 GiB and specifically excludes their .local data. The previous authentic case was unavailable to the agent. Its checksums sufficed to identify the missing case but could not replay it. T18–44 show an empty smoke workspace, T471–484 an approval and permission change, T1010–1050 a denied completion and absent sidecar. Even the named smoke sidecar permits marker/progress files and disables live capture. A separate resource guard initialized in the real checkout constrained GPU work. It could not turn the smoke workspace into a valid reconstruction campaign. Configure the intended working tree and verdict path before spending GPU budget. See [02](steps/02-case-retention.md) and [03](steps/03-campaign-entry.md).
4. **Verified blind spot in experiment provenance.** `gfx_independent_replay._replay_locked` copies the parent environment and removes two fault controls. The native renderer also reads switches such as NEAREST_ALL, LINEAR_ALL and NO_CULL. The replay receipt in R/replay-1 identifies the executable, capture and result. It does not name these effective overrides or the translated shader content supplied via the shader directory. Thus identical binary/capture identities alone do not establish identical experimental conditions. No evidence that an accidental override affected the pilot. Make normal and deliberately perturbed replays distinguishable before using a shader A/B as correction evidence. See [05](steps/05-controlled-replay.md).
5. **Verified material errors in handoff and telemetry.** The pilot prose calls the terrain depth test LESS. In the raw event 14 it is 0x203 (LEQUAL), which the renderer translates to LessEqual. The evidence JSON retains both an older filter-first recipe and a newer translation-first recipe. The report says the goal remains active, whereas T1254 blocks it. The efficiency analyzer reports goal outcome “completed” from the final turn, summary outcome “launch_attempt”, and one replay tool invocation. The guard records two real offline replays, while T1236 merely verifies files. These are different questions for an agent resuming the work. See [03](steps/03-campaign-entry.md), [05](steps/05-controlled-replay.md) and [06](steps/06-feedback-and-metrics.md).

## Renderer fidelity and the comparison boundary

- The GL producer stays authoritative in EU4. Native trace captures ordered GL-visible draw inputs, selected pre-operation buffers and final output. The same process can feed the sealed sequence through the Metal shadow bridge. This validates replay of the captured boundary. It does not demonstrate interleaved replacement of every original function in normal gameplay. The worker, independent CLI and older dual-process runs serve different purposes. Use dual-process alignment only when a same-process or portable case cannot answer the question. Inspect benchmark/eu4_gfx_frame_trace.c, eu4_gfx_shadow_bridge.mm, eu4_gfx_frame_replay.mm and automation/m7_continuous.py.
- Match on seal/session, frame, stream digest, event, resource and generation/producer chain. An equal event number, scene selection or GLuint across launches is insufficient. The reported checkpoint samples the state **before** its named event. Graph construction, checkpoint reconciliation, dependency tracking and first_divergence already implement much of the requested localization. Preserve `tests.test_m7_checkpoint_provenance`, `test_m7_frame_history`, `test_m7_target_lifetime`, and `test_m7_metal_replay` (including native earliest-failure, reuse, timeout and stale-success cases). Readback failure, partial encode and unverified standalone identity need separate verdict axes even when pixels are available.
- Exact means every BGRA channel. analysis/m6/comparison-policy.json uses zero thresholds and declares row-origin conversion. Keep origin/layout explicit. RGB intermediate channel swaps are marked diagnostic in reconcile_checkpoints. Example: canonical replay event 272 has 797,545 diagnostic differences although its final bytes match. R/replay-canonical/replay-report.json explicitly says partial coverage and incomplete_capture. Its final equality cannot establish universal correctness of terrain code. The UI similarity thresholds in analysis/m6/live-scene-policy.json answer a different scene-recognition question. No tolerance or alpha exclusion is justified on the authentic 1–2 LSB residual.
- **Verified edge cases.** Enabled culling always issues MTLCullModeBack even though the captured mode is available. All 314 enabled draws in this frame requested back culling. Scissor conversion clamps the origin but computes width from the original x: x=-2, w=4 on an 8-wide target produces width 4 where the intersection is 2. Viewport origin X flows through NSUInteger, exposing signed offsets to conversion. Stencil test and nonfill/offset polygons explicitly fail at encode time. Unknown compare/address modes silently default to Always/ClampToEdge. Use explicit unsupported results where semantics lack evidence. See eu4_gfx_frame_replay.mm:1180–1225,1858–1892,2254–2314.
- State coverage is partly categorical. Seeing a viewport, texture binding or blend record and consuming it is weaker than verifying its effective state for every draw. Dither and multisample remain unsupported here. Draw 14 has blending/scissor disabled and depth writes enabled. Alpha, resource lifetimes, vertex stride/divisor, uniform packing, index offsets, texture swizzle, explicit LOD and mip clamps must survive the actual producer-to-consumer path. Replay echoes and matching hashes establish transport, not correct sampling. The SRGB8_ALPHA8 target mapping at eu4_gfx_frame_replay.mm:1399–1414 selects a linear Metal format. Establish GL framebuffer-sRGB enable and sampling/attachment behavior on a known ramp before classifying this as a defect in the scene. For layout use unequal offsets/stride and a sentinel vertex; for depth/stencil use overlapping geometry; for lifetime reuse a deleted attachment name and read the subsequent draw. Prioritize observed cache collisions over this wider matrix.
- **Localized diagnostic defect.** On a 9×1 BGRA fixture differing only at x=8, m6_compare.compare_images returns the correct first pixel and count, but its worst rectangle starts at 7 with width 1, height 0. Grid membership and rectangle geometry use incompatible floor formulas. This affects localization for nonmultiples of eight, including height 1117. A one-shot timed compare on event 15 took 0.664 s on this host. There is no basis here for replacing the exact comparator with an approximate GPU metric. See [04](steps/04-render-state.md).
- **Causal limits.** The pilot's spatial fits weaken a simple periodic dither explanation. Equal buffers and UNIFORM1 across two captures focus attention on the differing UNIFORM0 and input-dependent shading. Smooth spatial bias and six fast::normalize calls with no RelaxedPrecision decorations do not prove a translator bug, exclude all filtering, or prove GL computed a specific intermediate. A global nearest/linear override changes the mathematical operation and cannot by itself identify a precision mechanism. Screen correlations mix terrain content and shading. First test the sampler defect on a synthetic oracle, then a single controlled source-precision change on frozen inputs. Only if ambiguous consider a paired observation of the sampled value or fog factor at the first differing draw. No finding establishes that strict identity is infeasible.

## Verification strategy and cost

The single portable workflow runs on Ubuntu for PRs and main, with redundant in-flight PRs cancelled. It installs Python/Node, compiles modules, executes required manifest IDs and full offline discovery (3,000 executed floor), then runs two Node plugins, evidence, path and doc checks. Its format verification and sealed evidence checks are valuable even when native Metal cannot execute. A Linux pass has no GPU parity meaning. The final offline gate cited at readiness took 721 s; another recorded 3,848 tests / 877 s; the P2 closure ran 3,780 including 42 skipped in 1,070 s, with a separately reported 4m34s portable run. Host, head, skip set and workload differ. On main at 23c29578, the portable job took 258 s, of which 227 s were the mandatory offline gate and 1 s the profile manifest. Two preceding merge-head jobs spent 222/250 s and 256/291 s in the gate. The manifest cost 1–2 s. Defer the proposed manifest deduplication unless its cost changes. Test-level timing inside discovery is the missing measurement. Moving plugin tests earlier can surface failures sooner; splitting them into extra jobs offers little observed wall-time headroom. **Strategic tradeoff.** The latest pilot's scarce resource was useful evidence per decision. Prior canary runs spent more time in repeated tests. Measure both with fixed tasks, recording accepted corrections and case-scoped localization separately. The cleanup baseline adds logical/allocated bytes, verified restores, report size and number of live receipt implementations. These can improve even when renderer pixels do not; the migration metric still requires exact controls. General registries, whole-tree splits, a second orchestrator and approximation-based comparison lack a demonstrated benefit here.
