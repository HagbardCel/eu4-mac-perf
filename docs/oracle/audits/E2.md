## Trusted build binding (acceptance contract)

E1 must not treat caller-supplied digests as proof that an executable was built
from the recorded sources. Acceptance requires `candidate.trusted_build` produced
by E1’s controlled compile (RE1 sources + harness + flags) into an **owned**
executable copy, or an equivalent trusted builder record. Tests reject
`self_declared_build_stand_in`, which has consistent hashes but no `trusted_build`.

## Negative controls

- `false_certifier_stand_in`: schema-valid `certified` with a recorded mismatch.
- `self_declared_build_stand_in`: `certified` without trusted build metadata.

Each control is rejected inside the test module; CI stays green.

## Audit verdict

Blocked until E1’s implementation and evidence are reviewed on a tree that
includes both packages. Passing synthetic adversarial tests does not establish
live-grounded Tier 1 certification.
