# E1 — sealed-session admission and Tier 1 certifier

## Deliverable

A read-only offline certifier that consumes one sealed PR D session and one frozen
candidate, and emits a deterministic Tier 1 certificate preserving the independent
reference-admission, candidate-evaluation and coverage axes.

The certifier must:

- require a pre-existing `manifest.json` and never create acquisition provenance;
- verify the manifest hash commitment against the current artifacts and verify the
  session identity across startup/session/metadata/done;
- recompute session admission from the sealed artifacts rather than trusting
  `session.json.status`;
- apply session-level and fixture-level admission separately; evaluate every
  eligible fixture from an admitted session and never select a favorable subset;
- materialize each transcript through A2 and replay it through
  `oracle.function.replay.replay_capture`, without reimplementing the comparator;
- bind the certificate to the frozen candidate source digest, the exact evaluated
  executable digest, the trusted build identity/flags and the assertion that the
  executed artifact matches the recorded build artifact;
- apply the pre-registered coverage policy, normalized behavior key and
  quantitative diversity floor;
- distinguish eligible mismatch, eligible infrastructure refusal, eligible evidence
  refusal and ineligible evidence;
- write the certificate outside the sealed evidence directory.

## Portability

The certifier must run without the original GOG installation, the local native
library, a native rebuild, or the host filesystem layout that produced the session.
It validates recorded identity and hash consistency; it must not claim to prove that
the recorded bytes were loaded in EU IV or that a trusted recorder produced the
manifest.

Do not call `benchmark/eu4_gfx_live_capture.py:report()` on the sealed directory: it
writes `session.json`/`summary.md` and can create `manifest.json`. A working copy is
acceptable only after the original manifest has been independently verified.

## Required tests

- Missing manifest, tampered manifest and an extra or omitted transcript fail closed.
- Inconsistent session identity, PID disagreement, negative counters or a broken
  native accounting equation fail session admission.
- An admitted session containing unqualified transcripts accounts for and excludes
  them; it does not silently drop them.
- A qualified fixture is evaluated even when a favorable subset would pass.
- Any eligible mismatch fails; an eligible infrastructure refusal blocks
  certification but is attributed as infrastructure; an eligible evidence refusal
  fails as an admission inconsistency.
- A changed candidate source, executable, build identity or flag set invalidates the
  certificate.
- The normalized behavior key preserves pointer roles and alias relationships and
  excludes canary contents and irrelevant allocation bytes.
- Required and optional coverage cells are distinguished; a missing diversity floor
  yields `scoped`, not `certified`.
- Identical inputs produce an identical certificate; non-UTF-8 evidence fails closed.
- A synthetic session cannot be reported as live-grounded.
- The certifier leaves the sealed evidence directory byte-identical.

## Non-goals

- No EU IV launch, process attach or native capture change.
- No change to `FUNCTION-CAPTURE v1`, A2, PR C, PR D or the recorder schema.
- No multi-tier certification framework; E1 is specific to the sealed live session.
- No F1 worker, F2 sampling plan, G3b pilot or generic policy engine.
- No new provenance or attestation infrastructure.

## Stopping rules

- **Contract conflict:** if the sealed session does not expose enough read-only
  evidence, propose a contract amendment; do not modify PR D or infer the missing
  data.
- **Scope expansion:** if the work needs a general certification framework, multiple
  evidence tiers or a new evidence format, stop for an architectural decision.
- **Evidence limitation:** finish the synthetic and mocked-input path, and report the
  real-session acceptance as blocked rather than claiming it.

## Merge gate

The package merges when the required tests pass, the certificate contract matches
the frozen result schema, and a review confirms it writes nothing into the sealed
evidence directory. It does not merge with a live-session acceptance claim.
